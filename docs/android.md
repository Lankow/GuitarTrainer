## Repository layout

This Android project follows the [shared browser/Android/future iOS structure](platforms.md). The future iOS project belongs at native/ios/ beside native/android/; both reuse src/. iOS is not generated or tested yet.

| Path | Purpose | Versioned? |
| --- | --- | --- |
| src/, tests/ | Shared React UI, audio/DSP, exercises and tests | Yes |
| capacitor.config.json | App identity, native project path and web output | Yes |
| native/android/ | Active Android source, manifest, resources, Gradle files and wrapper | Yes |
| docs/ | Product, architecture, setup, decisions and validation | Yes, alongside each change |
| dist/, dist-android/ | Browser and Android web builds | No |
| native/android/app/src/main/assets/ | Synced web assets and Capacitor configuration | No; regenerated by sync |
| native/android/**/build/, .gradle/ | Native outputs and caches | No |
| local.properties, signing keys/passwords | Machine SDK paths and signing credentials | Never |
| /android/, /ios/, .expo/ | Inactive historical prototype directories | No |

Keep both platforms in this GitHub repository. Use short-lived codex/ feature branches and review code plus documentation together. Do not create permanent desktop/Android branches or duplicate src/. The Android workflow builds a debug APK on pushes, pull requests and manual runs, retaining it as a CI artifact for seven days. Use GitHub Releases for deliberate public downloads later; signed AABs go to Play Console, not source history. Keep the release/upload key in secure private storage with a separate backup; a future CI release workflow must use GitHub Secrets. No signing secrets are needed for debug builds. The workflow has been configured locally; a successful remote run has not yet been observed.

## Setup and build

Use Node.js 24, npm, Android Studio, JDK 21 and Android SDK platform 36. The wrapper selects Gradle. Set JAVA_HOME to a compatible JDK and ANDROID_HOME to your SDK, or configure the SDK locally through Android Studio. Never commit local absolute paths. Run from the repository root:

```sh
npm ci
npm run android:sync
npm run android:open
```

In Android Studio, select a device and run the app. To build a debug APK in PowerShell:

```powershell
.\native\android\gradlew.bat -p native/android assembleDebug
```

On macOS/Linux use `bash native/android/gradlew -p native/android assembleDebug`. APK output: native/android/app/build/outputs/apk/debug/app-debug.apk. Repeat android:sync after changing shared code or plugins; Gradle alone does not rebuild the React application. android:build performs TypeScript checking and emits root-based assets in dist-android/. Browser builds and Pages deployment continue using dist/.

The initial ID is io.github.lankow.guitartrainer, versionName 0.1.0-alpha.1 and versionCode 1. Confirm identity before a production release. Launcher icons use the approved brand mark; splash resources remain provisional. Target/compile SDK 36 and minimum SDK 24 are configured; actual device support is unverified. No remote server URL is configured: the app bundles its web files. The existing Google Fonts stylesheet still requires a network connection; fallback fonts are available offline.

## Behavior and remaining work

Microphone capture uses Web Audio, Capacitor's permission handling and the existing worker detector. Audio remains local and is not recorded or uploaded. No native DSP or latency improvement is claimed. Browser visibility and native app-background events cancel audio, metronome and practice sessions; returning does not automatically resume. Android automatic data backup is disabled. Settings/profile data in the app's WebView are separate from the website's Chrome storage.

Permission-denied wording still references browser settings; platform-specific guidance is pending. Backup file downloads/imports, external links, system Back behavior, edge-to-edge layout and all translated screens require Android checks. Native file adapters may be necessary for export; do not assume browser download behavior works in WebView. Release signing, store assets, privacy policy, Data safety declarations, Play testing and release automation remain pending. Recheck Play requirements at release time.

## Physical acceptance checklist

Record device model, Android version, WebView version and date for each run. Intended first device: Motorola G34 / Android 15, not yet tested here.

1. Install, launch and reload; check nickname/preferences persistence and narrow-screen layout, system bars and keyboard.
2. Start microphone capture; grant permission, detect an open string, stop and verify Android's microphone indicator clears. Repeat with denial, regranting in app settings, and unavailable input.
3. Test worker loading, demo, each practice mode and note/octave matching against a real guitar. Measure misses with fast Spider Walk sequences rather than inferring performance from desktop tests.
4. During microphone startup and active sessions, press Home, lock the screen and switch apps. Verify capture/clicks stop, incomplete scores are not saved and returning requires a fresh start. Test repeated start/stop and permission-dialog transitions.
5. Verify metronome tempo, volume, interruptions and subjective timing; record measured latency separately if measured.
6. Test settings/walk JSON export/import, file picker, navigation/Back behavior, offline launch and upgrades preserving preferences.

## Launcher branding (2026-10-30)
The approved guitar-pick mark is shared with the in-app header/welcome screen through src/brandGeometry.ts. Adaptive icons use the transparent vector drawable at drawable-v24/ic_launcher_foreground.xml and a charcoal background. The same drawable supplies the monochrome layer for supported Android themed icons. The mark is centered at 60 dp tall within the 108 dp foreground canvas, inside the central 66 dp safe zone. Legacy/round PNGs and foreground densities are generated for mdpi through xxxhdpi. App accent changes affect the in-app SVG; launcher colors follow native resources or system theming. iOS icon generation remains deferred, and the published alpha asset/tag is unchanged.

To regenerate after editing the shared geometry, use Python with the optional developer dependencies in scripts/requirements-branding.txt, then run `python scripts/generate_brand_icons.py` from the repository root. Commit the resulting native resources with the geometry changes. The script emits an ignored build/branding-preview.png for visual review. These packages are not needed for npm/Gradle builds because generated native assets are versioned. Do not manually edit generated vector/PNG resources. The generator supports the master's absolute M/H/V/C/Q/Z paths; extending the source format requires updating the generator. SVG curves are sampled into polygons for native export. See [Android adaptive icon requirements](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive).

Verification (2026-10-30): generation was reproducible, Android XML parsed successfully, and geometry bounds fit both the central 66 dp square and circle. Reviewed the generated square/round/transparent preview. All 107 tests, TypeScript, browser build, Android web build/sync and local Gradle assembleDebug passed.
